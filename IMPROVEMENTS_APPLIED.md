# Full-Stack AI Agent 2.0 — targeted reliability and environment update

This delta bundle contains only files changed for this update. Extract it over the existing `Full_Stack_AI_Agent_2.0-main` folder, preserving the directory structure.

## Changes

- Hardened generated-project directory handling: project roots that are symlinks or resolve outside the generated-project root are rejected.
- Hardened atomic file writes: writes use a unique temporary file in the destination directory.
- Added deterministic backend verification for generated source, JSON manifests, generation metadata, OpenAPI shape, runtime environment loading and environment-file ignore rules.
- Added an optional deep-check pass that runs declared `typecheck`, `build`, `lint` and `test` scripts only when dependencies already exist; the verifier does not install packages automatically.
- Connected deep verification to the task API and added a **Deep full-stack check** button in the Report panel.
- Added environment-contract detection for common external providers and generically named third-party APIs. Server-side keys and database URLs are listed as placeholders in `backend/.env.example`; generated runtime adapters/configuration expose those values to backend code through the selected stack's runtime environment/config.
- Added examples and setup/security guidance in `backend/ENVIRONMENT.md` for generated projects. Real credentials are never generated by this update.
- Kept root `.env.example` for explicitly public frontend settings only. Server-only API keys, database URLs, service-role keys and OAuth secrets remain in the backend environment file. `.env` and `.env.*` are ignored by Git while `.env.example` is explicitly allowed.
- Strengthened generation prompts so API/database code must read runtime environment variables at the actual connection/request site and must not hardcode secrets or expose them to browser code.
- Added regression tests for path/write hardening, backend verification, provider and generic API environment detection, public/private environment separation, and runtime-adapter generation for supported backend stacks.

## Use

1. Extract this ZIP into the existing `Full_Stack_AI_Agent_2.0-main` folder and allow updated files to replace the originals.
2. Start the agent backend and frontend as usual.
3. When a project is generated, copy `backend/.env.example` to `backend/.env` and fill in the real database/API credentials locally. For a frontend setting explicitly marked public, use the root `.env.example` and copy it to the frontend's root `.env`.
4. Open a generated project and select **Deep full-stack check** to run optional backend checks. Ensure dependencies are already installed; the check does not run `npm install` or `pip install`.
5. Inspect the Report panel. A skipped check means it was not executed, not that it passed.

## Scope and limitations

This update provides environment-variable discovery, placeholder generation, runtime access helpers/configuration and prompt/verifier guardrails. It cannot implement an arbitrary third-party API just because a key exists: the API endpoint, authentication scheme, request/response contract and required feature still need to be described and generated. Only report a provider integration as working after the corresponding API client/route and tests pass. Generated applications still require stack-specific dependencies, credentials, database setup and realistic end-to-end testing.

## Continuous integration

The GitHub Actions workflow (`.github/workflows/reliability.yml`) runs a focused backend regression/security suite and frontend type-check/build/lint on pushes and pull requests. It is scoped to tests that do not require external provider credentials or live database services.
